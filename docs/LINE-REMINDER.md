# LINE 催繳提醒（未提出者リマインド）セットアップ

毎週決まった曜日・時刻に、**翌週（月〜日）の希望シフトに 1 日でも空欄が
残っている人**を LINE グループで名指しして催促する機能の設定手順。

```
Apps Script の時間主導トリガー（毎週 金 12 時台）
   └─ remindUnsubmitted()
        ├─ 翌週 7 日分のセルを見て「空欄が 1 つでもある人」を集める
        ├─ 「LINE連携」分頁で 姓名 → LINE userId を引く
        └─ Messaging API の push でグループに 1 通だけ送る
            （userId が分かっている人は @メンション付き）

姓名 ↔ userId の対応づけ（＝ @メンションの素）
   員工頁 [連結 LINE 帳號]           ← Google ログイン済み＝姓名は後端が知っている
     └─ LINE Login（同じ provider の LINE ログインチャネル）
          └─ /exec?code=… で戻り、id_token の sub を「LINE連携」分頁に書く
```

曜日・時刻・オンオフは **管理頁（admin.html）の「04 LINE 催繳提醒」**
から店長が変更できる。Apps Script を触る必要があるのは最初の 1 回だけ。

---

## 0. 前提

- LINE 公式アカウント（LINE Official Account）があること
- そのアカウントで **Messaging API を有効化**できること（無料プランで可）
- 公式アカウントをリマインド先の **グループトークに参加**させられること

> **メッセージ通数について**：LINE の無料プランは月 200 通まで。グループ送信は
> 「受信した人数」分カウントされるので、10 人のグループに毎週 1 通なら
> 月 40〜50 通ほど。テスト送信もこの枠を使う。

---

## 1. Messaging API を有効化してトークンを取る

1. [LINE Official Account Manager](https://manager.line.biz/) → 対象アカウント →
   **設定 > Messaging API** → 「Messaging API を利用する」
   （途中で LINE Developers のプロバイダー選択がある）
2. [LINE Developers Console](https://developers.line.biz/console/) → 作成された
   チャネル → **Messaging API 設定** タブ
   - **チャネルアクセストークン（長期）** を発行してコピー
   - **応答メッセージ：オフ**、**Webhook：オン** にする
     （自動応答が残っていると、群組で「綁定」と送るたびに定型文が返ってくる）
3. 同じ画面の下にある **「グループトーク・複数人トークへの参加を許可する」を
   オン**にする（LINE Official Account Manager の「設定 > アカウント設定」側に
   ある場合もある）。これがオフだと公式アカウントをグループに招待できない。

---

## 2. Apps Script 側の初期化

1. スプレッドシートの **拡張機能 > Apps Script** を開き、
   `apps-script/Code.gs` の中身を貼り直す（この機能を含むバージョンに）。
2. エディタで関数 **`setupLineReminder()` を 1 回実行**する。
   - 「承認が必要です」が出たら許可する。**トリガーを作る権限
     （script.scriptapp）が新しく必要になる**ので、ここを飛ばすと
     管理頁から「儲存設定」しても失敗する。
   - スクリプト プロパティに `LINE_CHANNEL_ACCESS_TOKEN` /
     `LINE_TARGET_ID` / `LINE_WEBHOOK_KEY` / `APP_URL` / `REMIND_*` /
     `LINE_LOGIN_*` / `LINE_LINK_STATE_SECRET` の雛形が作られ、
     `LINE連携` 分頁もできる。
   - 実行ログに **Webhook URL** と **LINE Login のコールバック URL** が
     出るので控えておく。
3. **プロジェクトの設定 > スクリプト プロパティ** を開いて実際の値を入れる。

   > ⚠ この画面は **値が空の行があると保存ボタンが効かない**。まだ決まって
   > いない項目には `PASTE_AUTO` のような置き字が入れてあるので、**消さずに
   > そのまま**にしておくこと（`PASTE_` で始まる値はコード側で「未設定」と
   > 判定される）。
   >
   > ⚠ **編集する前に必ずページを再読み込みすること。** この画面は保存時に
   > 「ブラウザが表示している全行」をまとめて書き戻す。開きっぱなしの画面で
   > 保存すると、その間に Webhook が書き込んだ値（`LINE_TARGET_ID` など）を
   > 古い内容で踏み潰してしまう。
   > 踏み潰した場合は、グループで誰かが「綁定」と送れば再記録される。

   | プロパティ | 入れる値 |
   | --- | --- |
   | `LINE_CHANNEL_ACCESS_TOKEN` | 1. でコピーした長期トークン |
   | `APP_URL` | 従業員が開く申請ページの URL（メッセージの末尾に付く。空なら付かない） |
   | `LINE_WEBHOOK_KEY` | 自動生成された値のまま（触らなくてよい） |
   | `LINE_TARGET_ID` | `PASTE_AUTO` のまま触らない。4. で自動的に入る |
   | `LINE_LOGIN_CHANNEL_ID` / `_SECRET` | 5. で作る LINE Login チャネルの値 |
   | `LINE_LINK_STATE_SECRET` | 自動生成された値のまま（触らなくてよい） |
   | `WEBAPP_URL` | **「デプロイを管理」に出ている `/exec` で終わる URL**（エディタからは自動取得できないので、基本的に手入力が必要） |

4. **デプロイ > デプロイを管理 > 鉛筆アイコン > バージョン「新バージョン」>
   デプロイ**。保存だけでは `/exec` に反映されない。

## 3. Webhook URL を登録する

LINE Developers Console の **Messaging API 設定 > Webhook URL** に、
`setupLineReminder()` のログに出たこの形の URL を貼って「更新」→「検証」：

```
https://script.google.com/macros/s/xxxxxxxx/exec?line={LINE_WEBHOOK_KEY}
```

**Webhook の利用：オン**も忘れずに。

> ⚠ **「検証」ボタンは 302 Found で失敗するが、それで正常。**
> Apps Script のウェブアプリは POST に対して必ず
> `script.googleusercontent.com` への 302 リダイレクトを返し、本体の応答は
> その先にある。LINE の検証ボタンはこのリダイレクトを追わないので
> 「200 以外が返りました (302 Found)」と出るが、**実際のイベント配信は
> リダイレクトを追ってくれるので問題なく届く**。
> 検証ボタンの結果は無視して、次の「4. グループを登録する」で
> 実際の動作を確認すること。
>
> （401 Unauthorized が出る場合はこれとは別問題。`/dev` を登録している。）

> ⚠ **必ず `/exec` で終わる URL を使うこと。**
> Apps Script には 2 種類の URL がある。
>
> | URL | 何者か | LINE から叩くと |
> | --- | --- | --- |
> | `…/{デプロイID}/exec` | 公開されている本番 | 匿名でも 200 |
> | `…/{スクリプトID}/dev` | 開発用。**開発者本人のログインが必要** | **401 Unauthorized** |
>
> 厄介なのは、`ScriptApp.getService().getUrl()` を**エディタから実行すると
> `/dev` が返る**こと。`setupLineReminder()` はこれを検知して「/exec を
> `WEBAPP_URL` に入れてから実行し直してください」と促すようにしてあるので、
> ログにそう出たら「デプロイ > デプロイを管理」の `/exec` URL を
> `WEBAPP_URL` に貼ってからもう一度実行する。
> （`/dev` と `/exec` は ID の種類が違うので、文字列を書き換えて変換すること
> はできない。）

> Apps Script は HTTP ヘッダーを読めないため `x-line-signature` の検証が
> できない。代わりに URL の `?line=...` を合言葉にして、知らない相手からの
> POST を弾いている。この URL は LINE の設定欄以外に貼らないこと。
> 万一漏れたら `LINE_WEBHOOK_KEY` を作り直して Webhook URL を差し替える。

---

## 4. グループを登録する（＝ Webhook の動作確認も兼ねる）

1. 先に `LINE_CHANNEL_ACCESS_TOKEN` を入れておく（返信メッセージに必要）。
2. リマインドしたい **LINE グループに公式アカウントを招待**する。
   参加した時点でそのグループが `LINE_TARGET_ID` に記録され、
   使い方の案内が自動で流れる。
   **この案内が流れれば Webhook は生きている**（検証ボタンが 302 で
   失敗していても関係ない）。
3. 案内が出なかったときは、グループ内で誰かが **`綁定`** と送ってみる。
4. どちらでも反応がなければ、管理頁の「04 LINE 催繳提醒」で
   「提醒的 LINE 群組」が **已設定** になっているかを見る。
   ここが已設定なら、グループ ID の記録自体は成功している
   （返信が出ないのはトークン未設定か応答設定の問題）。

## 5. @メンションできるようにする（LINE Login・推奨）

名指し（@メンション）には LINE の **userId** が要る。これを確実に取るために、
従業員ページに「連結 LINE 帳號」ボタンを置いている。本人はすでに Google
ログイン済み＝**後端が姓名を知っている**状態なので、ボタンを押して LINE の
同意画面で許可するだけで紐付けが終わる。**LINE の表示名が班表の姓名と違って
いても関係ないし、本人が姓名を入力する必要もない。**

### 5-1. LINE Login チャネルを作る

> ⚠ **必ず Messaging API チャネルと同じプロバイダーの下に作ること。**
> userId はプロバイダー単位で発行される。同じプロバイダーならチャネル種別が
> 違っても同じ userId になるが、別プロバイダーに作ると **ここで取れた userId で
> @メンションしても LINE に弾かれる**（連結完了画面に警告が出る）。

1. [LINE Developers Console](https://developers.line.biz/console/) で、
   1. で使ったプロバイダーを開く → **新規チャネル作成 > LINE ログイン**
2. アプリタイプは **ウェブアプリ**
3. **LINE ログイン設定 > コールバック URL** に、ウェブアプリの `/exec` URL を
   **クエリなしでそのまま**登録する（`setupLineReminder()` のログにも出る）：

   ```
   https://script.google.com/macros/s/xxxxxxxx/exec
   ```

4. **チャネル基本設定** から次の 2 つをコピーして、Apps Script の
   スクリプト プロパティに入れる

   | プロパティ | 値 |
   | --- | --- |
   | `LINE_LOGIN_CHANNEL_ID` | LINE ログインチャネルの **チャネル ID** |
   | `LINE_LOGIN_CHANNEL_SECRET` | 同 **チャネルシークレット** |

   > `ScriptApp.getService().getUrl()` が実際の公開 URL と食い違う場合
   > （`/dev` が返るなど）は、`WEBAPP_URL` に `/exec` の URL を明示する。
   > こことコールバック URL の登録値は 1 文字でも違うと LINE に弾かれる。

5. これで従業員ページの身分カードに「連結 LINE 帳號」ボタンが出る
   （`whoami` が `lineLoginReady` を返すようになるため）。

### 5-2. 従業員側の操作

員工頁 → **「連結 LINE 帳號」** → LINE の同意画面で許可 → 「連結完成」画面 →
「回到排班申請頁」。以後その人は @メンション対象になる。解除したくなったら
同じ場所の「解除連結」から。

### 5-3. 予備手段：グループで `綁定` と送る

LINE Login を用意しない／使えない場合は、グループ内で本人に送ってもらう
方式も残してある。

| 送る文字 | 動き |
| --- | --- |
| `綁定` | LINE の表示名が班表の姓名と一致すれば自動で紐付け |
| `綁定 林欣霈` | 班表の姓名を明示して紐付け（表示名が違う人はこちら） |

台湾の店舗なので案内は **`綁定`** に統一してあるが、`連結` / `連携` /
`連攜` / `link` も同じ意味で受け付ける（過去の案内を見た人向けの別名）。
姓名は半角スペースあり・なしどちらでもよい。
それ以外の発言には一切反応しない（「我要綁定」のように文中にあるだけでは
動かない。行頭に来たときだけ指令とみなす）。

結果はどちらの方式でもスプレッドシートの **`LINE連携` 分頁**
（姓名／LINE 暱稱／userId／更新時間）に入る。姓名だけ後から手で直してもよい。
LINE Login で連結し直すと、同じ姓名の古い行は自動で消えて 1 対 1 に保たれる。

**紐付いていない人も催促対象からは漏れない**。名前がテキストで並ぶだけで、
@メンションが付かないだけ。管理頁の一覧で「未連結 LINE」と表示される。

## 6. 動作確認とスケジュール設定

管理頁（`admin.html`）の **「04 LINE 催繳提醒」**：

1. 下に出る 3 項目（Channel access token / 提醒的 LINE 群組 / Webhook 密鑰）が
   すべて **已設定** になっていることを確認
2. 現在の未提出者一覧を確認（誰が @ 可点名かもここで分かる）
3. **「立刻試送到 LINE 群組」** で 1 通テスト送信（グループ全員に届く）
4. チェックボックスをオンにして曜日・時刻を選び、**「儲存設定」**

初期値は **金曜 12 時台**。Apps Script の週次トリガーは「〇時台」の精度しか
ないので、実際の送信は選んだ時間帯の中のどこかになる。時刻の基準は
`appsscript.json` の `timeZone`（現在 `Asia/Taipei`）。

エディタから直接試すこともできる：

| 関数 | 動き |
| --- | --- |
| `previewReminder()` | 送らずに本文だけログに出す |
| `sendReminderNow()` | 今すぐ本番送信 |
| `remindUnsubmitted()` | トリガーと同じ動き（オフなら何もしない） |

## 仕様メモ

- **対象週**：実行日を含む週の翌週（月〜日）。従業員ページが「下週」として
  出しているのと同じ 7 日間。
- **未提出の判定**：その 7 日のうち **1 マスでも空欄なら対象**。`排休` が
  入っていれば「提出済み」として数える。
- **全員提出済みなら送らない**（無駄な通知を出さない）。
- 翌週の月份分頁がまだ無いときは送らずエラーを記録する。月が変わる前に
  `addNextMonthSheet()` を実行しておくこと。
- **@メンションが LINE に弾かれたら、名前だけのテキストで自動的に送り直す**。
  グループを抜けた人の userId が `LINE連携` 分頁に残っていると起きるので、
  その行は削除しておくとよい。
- 送信履歴は `REMIND_LAST_SENT`（スクリプト プロパティ）に 1 件だけ残る。

## よくあるエラー

| 表示 | 原因と対処 |
| --- | --- |
| `後端還沒更新到含有這個功能的版本` | `Code.gs` を貼り直して**新バージョンをデプロイ**する |
| `line_token_missing` | `LINE_CHANNEL_ACCESS_TOKEN` が未設定／`PASTE_` のまま |
| `line_target_missing` | 公式アカウントがグループに居ない、またはグループで `綁定` を送っていない |
| `line_api_401` | トークンが無効・失効。発行し直す |
| `line_api_403` | Messaging API が無効、またはグループ参加が許可されていない |
| `line_api_429` | 月間のメッセージ通数の上限 |
| Webhook 検証が **302 Found** | Apps Script の仕様。**無視してよい**（実配信は動く）。4. で実動作を確認する |
| Webhook 検証が **401 Unauthorized** | `/dev` の URL を登録している。`/exec` で終わる URL に直す（上の 3. の警告を参照） |
| Webhook 検証が 404 | デプロイを作り直して URL が変わった。新しい `/exec` を登録し、`config.js` の `API_URL` と `WEBAPP_URL` も更新する |
| `no_month_sheet_for_next_week` | 翌週の月份分頁が無い → `addNextMonthSheet()` |
| 「儲存設定」で権限エラー | `setupLineReminder()` をエディタで 1 回実行して承認する |
| スクリプト プロパティが保存できない | 値が空の行がある。`PASTE_AUTO` などの置き字を入れる（空行があると画面全体が保存できない） |
| 招待して案内も流れたのに「提醒的 LINE 群組」が未設定 | 開きっぱなしのプロパティ画面で保存し、`LINE_TARGET_ID` を古い値で上書きした。グループで「綁定」と送れば再記録される |

### LINE Login（連結ボタン）まわり

| 表示 | 原因と対処 |
| --- | --- |
| 員工頁にボタンが出ない | `LINE_LOGIN_CHANNEL_ID` / `_SECRET` が未設定（`whoami` が `lineLoginReady:false` を返している） |
| LINE 側で「400 Bad Request / redirect_uri」 | コールバック URL の登録値と `WEBAPP_URL`（既定は `/exec`）が完全一致していない |
| 「連結逾時」 | 同意画面を 10 分以上放置した／`state` が壊れた。押し直せばよい |
| 「連結失敗（http_400）」 | チャネル ID／シークレットが LINE ログインチャネルのものになっていない |
| 連結は完了したのに警告が出る | **LINE ログインチャネルが Messaging API と別プロバイダー**、または本人がまだ群組に入っていない |
| 連結済みなのに @ されない | `LINE連携` 分頁の姓名が班表の姓名と 1 文字でも違う（前後の空白に注意） |
